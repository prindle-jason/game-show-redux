# Next milestone: real round import (zip → live queue)

**Status: Partially done.** `@gameshow/schema` (`listMediaRefs`, `roundMediaManifestSchema`/`RoundMediaManifestEntry`) and `player-app`'s import path (`round-import.ts`, wired into the lobby's "Import round" file input) are implemented and tested, verified against hand-built test zips (constructed directly with `jszip` in test code, since `builder-app` doesn't produce real ones yet). `builder-app`'s export side — the other half of the "What" section below — has not been built; it now falls to `docs/milestone-builder-jeopardy-final-jeopardy.md`, which was waiting on this piece to land before authoring media attachment.

## Context

Every round type currently reaches a live game as a hardcoded fixture (`player-app/src/fixtures.ts`) — there is no "load a round file" UI anywhere. Meanwhile the media-upload milestone already built and proved the harder half of this problem: `uploadRoundMedia()` (`player-app/src/media-upload.ts`) uploads real `Blob`s to `party`'s signed-token `/media/upload` route and is already exercised end-to-end by every fixture button in the lobby (`App.tsx`). What's missing is entirely the *authoring/packaging* side: a zip format that `builder-app` can export into and `player-app` can import back out of, ending in a call to the exact `uploadRoundMedia` + `add-round-to-queue` path that already works.

This unblocks `docs/milestone-builder-jeopardy-final-jeopardy.md`, which deferred real media authoring specifically because this piece didn't exist yet.

## Design decisions

- **Zip layout: `round.json` at the root, `assets/manifest.json`, and one file per asset at `assets/<assetId>` (no extension).** The manifest is `Array<{ assetId: string; kind: 'image' | 'audio' | 'video'; contentType: string }>`, written by `builder-app` from each attached file's real `blob.type`. This avoids inventing an extension→MIME guessing table on import — content type travels explicitly, the same way `RoundMediaAsset` already carries it. **Note the manifest's `kind` excludes `'slideshow'`**: a `MediaRef` of `kind: 'slideshow'` bundles several `assetIds`, but each one gets its own manifest entry as a plain `kind: 'image'` file (mirrors the existing convention in `player-app/src/fixtures.ts`) — `'slideshow'` is a `MediaRef`-level kind only, never a per-file one. `builder-app`'s export must decompose slideshow fields this way or `player-app`'s import will reject the round-trip with a kind-mismatch error.
- **A shared `listMediaRefs(round: Round): MediaRef[]` walker, added to `@gameshow/schema`.** `party/src/rounds/index.ts` already has this exact per-round-type walk (`resolveMedia`/`listMediaUrls`, one implementation per round type — see `resolveJeopardyMedia`, `resolveFinalJeopardyMedia`, `resolveWheelMedia`), but `party` isn't something `builder-app`/`player-app` import from. Rather than duplicate the walk in two more places, add a schema-level equivalent that just collects `MediaRef`s instead of resolving them — `builder-app` uses it to know which assetIds it must bundle, `player-app` uses it to know which assetIds the zip must contain, and it's one more reusable piece of the round-type plugin contract instead of two copy-pasted ones.
- **Import validation is all-or-nothing (same zod-at-trust-boundary pattern used everywhere else).** Parse `round.json` via `roundSchema.safeParse` → reject if invalid. Parse `manifest.json`. Cross-check `listMediaRefs(round)`'s assetIds exactly match the manifest's keys and that every manifest entry has a matching zip file (no missing, no extra) → reject the whole import on any mismatch rather than partially importing. Re-validate each asset's size/content-type against `MEDIA_LIMITS` (`@gameshow/schema/media.ts`) client-side before requesting upload tokens — the server enforces this too, but failing fast with a clear message beats a generic 413 from the upload route.
- **`builder-app`'s draft stores keep attached files in a side table, not inside the schema-shaped draft.** E.g. `assets: Record<assetId, File>` alongside the draft's `ClueContent` fields (which only ever hold `{ kind, assetId }` refs, matching `MediaRef` exactly) — mirrors how `wheel-draft-store.ts` already keeps a flat draft shape; export reads both the draft data and the asset table to build the zip.
- **Import is additive, not a replacement for the fixture buttons.** A new "Import round" file input (`accept=".zip"`) in the lobby (`player-app/src/App.tsx`), alongside the existing fixture buttons — those remain useful for fast local testing without needing a zip file on hand.

## What

- **`@gameshow/schema` — done.** Added `listMediaRefs(round: Round): MediaRef[]`, one small case per round type (mirrors the `roundTypeDefinitions` / `resolveMedia` precedent already in `party`), plus `roundMediaManifestSchema`/`RoundMediaManifestEntry` for `assets/manifest.json`.
- **`player-app` — done.** `round-import.ts` unzips via `jszip` (now a `player-app` dependency), parses/validates as above, builds a `RoundMediaAsset[]` from the manifest + files, then calls the existing `uploadRoundMedia(round, assets, requestMediaUploadTokens, mediaBaseUrl)` and `send({ type: 'add-round-to-queue', round })`, exactly like the fixture buttons already do. A lobby file input (`accept=".zip"`) is wired to this function, with an error banner on rejection.
- **`builder-app` — not started.** Per-editor, a file input on each media-capable `ClueContent` field, storing the picked `File` in the draft's asset side-table and a live local preview via `URL.createObjectURL` (same shape as `ResolvedMediaRef.url`, so `round-ui` preview components can stay agnostic to "local file" vs. "uploaded URL" if that unification is worth it). Export zips `round.json` + `assets/manifest.json` + one `assets/<assetId>` file per attached asset, per the layout above — remember the slideshow→per-file-`'image'` decomposition. This work now belongs to `docs/milestone-builder-jeopardy-final-jeopardy.md`, which was deferring media authoring until this piece existed.
- Tests: `listMediaRefs` per round type including a media-free type like Wheel returning `[]` (**done**, in `packages/schema`); import round-trips a hand-built zip back into a valid `RoundMediaAsset[]` + `Round`, rejects a zip with a `round.json` failing schema validation, a missing asset, an extra unreferenced asset, a kind-mismatched asset, or an oversized/wrong-content-type asset (**done**, in `packages/player-app/src/round-import.test.ts`, using hand-built test zips since `builder-app` doesn't export real ones yet); export produces the manifest/asset layout correctly for each media-capable round type (**not started** — depends on the `builder-app` work above).

## Why

Splitting this out as its own milestone (rather than folding it into the Jeopardy/Final Jeopardy builder work) keeps two different problems from being solved at once: "build a form for authoring categories/clues" doesn't require also inventing a round-trip file format. It also means Wheel of Fortune's builder (media-free) didn't need to wait on this, and once this lands, media authoring becomes available to *all* round types' editors for free, not just the two built after it.

## Done when

- A round exported from `builder-app` with at least one attached image and one attached audio clip imports successfully in `player-app`'s lobby and plays correctly in a live two-tab game (media renders/plays for both host and contestant). **Blocked on `builder-app`'s export side — see `docs/milestone-builder-jeopardy-final-jeopardy.md`.**
- Corrupting the zip in each of the ways above (bad `round.json`, missing asset, extra asset, kind mismatch, oversized asset) produces a clear rejected-import error rather than a partial import or a crash. **Done** — covered by `round-import.test.ts` against hand-built test zips.
- `typecheck`, `lint`, `test`, and `build` stay green across the monorepo. **Done** for the schema + player-app pieces implemented so far; re-verify once `builder-app`'s export lands.
